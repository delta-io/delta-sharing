# Learning journal 2026-11-21

### 2026-11-21: Python connector — Match mid-stream CDF failures by exception type and marker, not a broad message regex
**Context:** In PR #1045 a reviewer caught that a broad `[Ii]nvalid|JSON|json` matcher under `pytest.raises(Exception)` also accepted unrelated pre-stream errors (`Invalid timestamp`, profile-parse); the fix split cases so a mid-stream CDF failure must raise `json.JSONDecodeError` whose `doc` contains the server's stream-failure marker, while up-front rejections stay typed `HTTPError`.
**Rule:** Assert a mid-stream streaming failure by its exception type and the server's marker in the unparseable payload, and assert up-front rejections as HTTP errors, rather than one broad message regex that also matches unrelated pre-stream errors.

### 2026-11-21: Scala tests — Sort share/table list responses before comparing; element order is unspecified
**Context:** In PR #1045 `test_list_shares` and `_verify_all_tables_result` were changed to sort both sides by key before asserting equality, because the sharing protocol does not define the order of shares/tables in list responses and OpenSharing returns them in a different order than the reference server.
**Rule:** Compare list-endpoint responses (shares, tables) by sorting both sides on a stable key rather than asserting exact element order, which the protocol leaves unspecified and varies per server.

### 2026-11-21: Scala tests — Load integration test catalog from one shared data file, not hardcoded per server
**Context:** In PR #1040 the reference server's test setup stopped hardcoding ~40 shares/tables in `TestResource.scala` and instead loads them from the shared `dev/integration-tables.json` catalog (also consumed by opensharing-test-server) via `Test / unmanagedResourceDirectories`.
**Rule:** Define the integration-test share/table catalog once in a shared data file consumed by every server implementation under test, rather than duplicating the fixture definitions in each server's code.
