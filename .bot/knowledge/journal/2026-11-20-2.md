# Learning journal 2026-11-20

### 2026-11-20: Scala tests — Compare parsed JSON, not response substrings
**Context:** Porting the client integration tests to OpenSharing (#1043) replaced exact-substring assertions on metaData/file action lines with parsed-JSON comparisons, because a different server emits semantically equal JSON with a different field order.
**Rule:** Assert on parsed JSON nodes, not exact substrings, since JSON field order is not significant and varies across server implementations.

### 2026-11-20: Scala tests — Read per-run credentials from the profile, never hardcode
**Context:** Running Spark integration tests against OpenSharing (#1044) broke the hardcoded endpoint/bearerToken because OpenSharing mints a fresh recipient token per run; the fix reads endpoint, token, and shareCredentialsVersion from the run's profile provider.
**Rule:** Read the endpoint and bearer token from the test run's profile instead of hardcoding them, because some servers mint fresh recipient credentials per run.

### 2026-11-20: Scala tests — Assert on stable error signals, not exact codes or messages
**Context:** OpenSharing integration tests (#1044) needed error assertions loosened to tolerate differing error codes (RESOURCE_DOES_NOT_EXIST vs BAD_REQUEST), differing CDF failure text, and storage-scheme support differences (wasb returns 501 NOT_IMPLEMENTED; abfs/abfss only).
**Rule:** In cross-implementation integration tests assert on stable signals like HTTP status and error presence, not on an exact errorCode string or message text, which differ per server implementation.
