# Learning journal 2026-11-28

### 2026-11-28: Python connector — Report post-HTTP-200 stream errors via a trailing EndStreamAction, not the status code
**Context:** PR #1035 added EndStreamAction handling to the Python client's queryTable/queryTableChanges paths: errors occurring after the server has already sent HTTP 200 can't change the status code, so they arrive in a trailing end-of-stream action carrying errorMessage and httpStatusErrorCode; a mid-stream CDF failure now surfaces as a typed DeltaSharingServerError (e.g. status 403) with the server's own message instead of a JSONDecodeError on an unparseable last line.
**Rule:** For a streamed response that may fail after HTTP 200, opt in to a trailing end-of-stream action, surface its error and status code as a typed exception, retry only on 429/5xx, and treat a promised-but-missing trailing action as a truncated, retryable response.

### 2026-11-28: Python connector — Add an endpoint-specific capability per-request, not to session headers
**Context:** PR #1035 adds includeendstreamaction=true only on queryTable/queryTableChanges because only those endpoints return it; it is merged into the request-level capabilities header rather than set on the session, and requests' header merge keeps Authorization/User-Agent while replacing only that one header.
**Rule:** Scope a capability that only some endpoints honor to a per-request header merged over the session value, never to session-global headers, so it neither leaks to other endpoints nor drops the session's auth headers.

### 2026-11-28: Python tests — Don't build expected values from the code (or state) under test
**Context:** In PR #1035 a reviewer flagged tests that constructed the expected error message with the same helper production used, and an assertion that read a capability back from the same session header production copies from — both were trivially true and tested nothing; fixes assert full literal strings and inspect the actual prepared outgoing request.
**Rule:** Assert against full literal expected strings and the actual outgoing request, never against a value reconstructed by the production code path or read back from the same state the code copies from, since such assertions are tautologically true.
